## Locked decisions

These were agreed before implementation. Do not reopen them unless the user asks.

- Port: `8000` (`http://localhost:8000`)
- One Docker container. FastAPI serves the static Next.js export at `/` and JSON APIs under `/api`.
- SQLite file on a Docker volume so data survives container restarts. Create the DB if it is missing.
- Schema is normalized tables, not a JSON blob.
- New users start with the current frontend demo cards and columns.
- Reopened by the user on 2026-10-15 (Part 11): real user accounts with server-side sessions and multiple boards per user replace the client-only login and one-board limit. The demo account `user` / `password` is still seeded.
- Users and the AI can create, edit, move, and delete cards.
- Users and the AI can add, rename, and delete columns.
- AI chat history lives in `sessionStorage` only (survives refresh, dies when the tab session ends). Not stored in the database.
- When the AI changes the board, it returns a full replacement board. The backend saves that replacement and the UI refreshes from it.
- OpenRouter model: `openai/gpt-oss-120b`. Key from root `.env` as `OPENROUTER_API_KEY`.
- Python deps via `uv`. Frontend is the existing Next.js app in `frontend/`.
- Color scheme from root `AGENTS.md`. New UI uses those tokens. No emojis.

## Implementation decisions from completed parts

- Backend route responses return the full `BoardData` shape after every board mutation so the frontend can replace its local view from the saved source of truth.
- Column/card ids are text ids. Seed data keeps the original demo ids (`col-backlog`, `card-1`, etc.); newly created records are generated by the backend.
- `POST /api/cards/{id}/move` accepts `{ "columnId": string, "position": number }` rather than drag/drop target ids.
- `POST /api/cards` accepts `{ "columnId": string, "title": string, "details": string }`.
- Frontend column rename commits on blur or Enter. Escape cancels the in-progress rename.
- Frontend card edit is inline on each card and saves through `PATCH /api/cards/{id}`.
- Frontend e2e tests run against the Docker app on `127.0.0.1:8000`, not the Next dev server. They reset backend state with `PUT /api/board` before each test.
- Backend tests run with the `ghcr.io/astral-sh/uv:python3.13-bookworm` Docker image and a temporary SQLite file.
- `POST /api/ai/ping` sends only `What is 2+2? Reply with only the number.` to OpenRouter. It does not send Kanban JSON.
- `POST /api/chat` accepts `{ "message": string, "history": {role, content}[] }`. History is not stored. The model receives the current board JSON plus user/assistant history.
- The model must return structured JSON: `{ "message": string, "board": BoardData | null }`. A valid board replaces the saved board. An invalid board is discarded and the reply says the update was not applied.
- The signed-in board opens an AI chat sidebar by default. It can be closed and reopened. History is stored in `sessionStorage` under `pm-chat-history`.
- The sidebar sends prior user/assistant messages as `history` and the new text as `message`. A non-null `board` in the response replaces the visible board immediately.

## Suggested implementation notes

- Prefer the simplest working version. No extra auth, no extra entities, no chat persistence.
- Aim for about 80% test coverage when it is sensible, but do not add low-value tests just to hit that number. Focus on tests that protect real behavior; missing 80% is acceptable when the remaining coverage would be artificial.
- Frontend tests: Vitest + Testing Library in `frontend/src`, Playwright in `frontend/tests`. Point e2e at the container (`http://localhost:8000`) once the app is served from Docker.
- Backend tests: `pytest` via `uv`.
- When a part changes UI, verify in the browser, not only with tests.
- Identify root cause before fixing bugs.
